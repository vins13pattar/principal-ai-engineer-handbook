The Learn track is sixteen modules, read roughly in order. Each one follows the same structure
end to end — an executive summary and mental model up front, an architecture and deep dive in the
middle, and failure modes, trade-offs, and interview questions before the hands-on lab. That
consistency is deliberate: once you know the shape of one module, you know how to navigate all of
them, and how to write the next one.

## Required structure

Every module page carries these sections, in this order. `scripts/lint-content-structure.ts` fails
CI if one is missing.

1. **Executive Summary** — what this module covers and who needs it, in one paragraph.
2. **Mental Model** — the one idea that makes everything else in the module make sense.
3. **Architecture** — how the pieces fit together, with a diagram.
4. **Deep Dive** — the mechanics: what actually happens and why.
5. **Implementation** — real code, not pseudocode.
6. **Production Example** — how this shows up in a system that takes real traffic.
7. **Failure Modes** — the specific ways this breaks, and how you'd know.
8. **Trade-offs** — what you give up by choosing this approach over the alternatives.
9. **Security** — the attack surface this introduces and how it's closed.
10. **Performance** — the numbers that matter and how to measure them.
11. **Scaling** — what changes at 10x and 100x load.
12. **Interview Questions** — the questions this material actually answers.
13. **Hands-on Lab** — a link to the companion lab in [Build](/build/).
14. **References** — primary sources, not blog posts about blog posts.
15. **Revision History** — what changed, and when.
