## At a Glance

A **decision model** answers typed questions about a piece of state — a ticket, an email, a page, a
JSON document — and returns a probability distribution over the answers you allowed, instead of
generating text. It cannot produce an answer outside the set you defined, and it does not write
tokens one at a time: the input is read once and every allowed answer is scored.

The category launched under TypeSafe AI's name for it, **System One models** — the fast, intuitive
half of Kahneman's two systems, set against an LLM's slower, deliberate one. "Decision model" is
what Cloudflare and the open-source projects call it, and the more descriptive of the two.

What it is for is the part of a production AI system that is not generation: **routing,
classification, gating, and an agent's choice of next action**. Those calls pay an LLM's latency
and cost for a bounded answer, and get back text that has to be parsed into one.

```text
state + { name: question, … } → one forward pass → { name: answer + probabilities, … }
```

Four products in sixteen days:

| Product | From | Released | Weights | Shape |
| --- | --- | --- | --- | --- |
| Jev | TypeSafe AI | 2026-09-15, early access | Closed, hosted | Text in; the API the others copied |
| Laya | Convai Innovations | 2026-09-18 | Apache-2.0 | A 421M encoder; options scored at `[MASK]` tokens |
| Decisions API | OpenAI | 2026-09-29, limited preview | Closed, hosted | Built on GPT-6 Luna. No public reference yet |
| Clef, Clef-flash | Cloudflare | 2026-10-01 | Apache-2.0 | 27B and 9B on frozen Qwen backbones; images accepted; Jev-API compatible |

## Key Concepts

| Concept | What it does |
| --- | --- |
| State | The input being judged. A string, object, or array in Jev's API |
| Question | A named, typed decision about the state. Several share one state in one request, and answers return under the names you chose |
| `noul` | Yes or no. Returns a probability from 0 to 1 |
| `choice` | One of a labelled set of options. Returns the top option and a probability per option |
| `score` | A position on an ordered rubric. Returns a probability-weighted score that can fall between levels |
| Probabilities | The distribution over allowed answers — the thing that makes "escalate when unsure" implementable at all |
| `confidence` | **TypeSafe's summary of how concentrated the distribution is** — 1 when all mass is on one answer, 0 when it is spread evenly. A measure of sharpness, not of being right |
| Calibration | Whether an answer given 0.9 is right 90% of the time. The property a threshold depends on, and the one least measured so far |
| Escalation threshold | The probability below which the decision tier hands off to an LLM or a person. Yours to fit, on your traffic |
| Non-autoregressive | No token-by-token decoding. Clef reads the input once (prefill only) and scores the allowed answers in parallel |
| Fine-tuning | How a general decision model becomes good at your decisions. Laya's card is explicit that its headline accuracy depends on it; Cloudflare launched an RL fine-tuning service alongside Clef |

## Common Gotchas

- **`confidence` is not calibration.** TypeSafe defines it as how concentrated the distribution
  is, and its own docs never claim the number matches observed accuracy. A model can be maximally
  confident and wrong, and an uncalibrated one is confident and wrong systematically. Before a
  threshold gates anything, measure what fraction of answers above it are actually right — on
  your traffic, not the benchmark's.
- **The shipped probabilities may not be calibrated either.** Laya's own card reports an expected
  calibration error of 0.466 out of the box, falling to 0.081 only after temperature fitting.
  Cloudflare trains Clef with a calibration loss and publishes no calibration metric. Assume you
  have to fit it.
- **"Cannot hallucinate" describes the output type, not the answer.** A typed answer cannot be
  malformed or outside the set. It can still be the wrong member of the set, stated with a high
  probability, in a form that skips every check text output would have triggered.
- **Every benchmark is somebody's marketing.** Cloudflare's latency table is Cloudflare comparing
  itself with a competitor. Laya's comparison uses Jev numbers it did not reproduce. No independent
  evaluation exists yet. The decision that matters — whether a decision tier is right often enough
  on your questions to skip the LLM — is not one any of them answers for you.
- **Zero-shot is not the product.** Laya scores below a majority-class baseline before
  fine-tuning. "General decision model" means a good starting point to specialise, not a drop-in
  router.
- **Option count is a quality variable.** Laya's card reports accuracy falling sharply at high
  option counts (0.425 on a 77-label set). A `choice` with 200 options is a different problem from
  one with 5, even though the API accepts both.
- **API compatibility is not behavioural compatibility.** Clef accepts Jev's request shape, so
  switching is an endpoint change. The probabilities that come back are a different model's, and
  every threshold fitted on the old one has to be fitted again.
- **The OpenAI API is not documented yet.** As of 2026-10-08 there is no public request schema,
  endpoint reference, or price, and access is limited. Anything specific you read about it is
  coverage, not documentation.
